# Emby 新用户模板权限复制

## 故障原因与验证

Emby 4.10.0.40 的复制选项接口 `GET /Users/CopyDataOptions` 返回的用户策略 ID 是 **`userpolicy`**。旧代码使用 `UserPolicy`，服务端仍返回 HTTP 200，但忽略权限复制，新账号使用默认权限。

在当前服务器使用临时账号对照验证：

| 创建选项 | 转码 / Remux | 同时流限制 | 媒体库范围 | 下载权限 |
|---|---|---|---|---|
| `UserPolicy`（旧） | 全部允许 | 0，不限制 | 全部库 | 允许 |
| `userpolicy`（修复） | 与模板一致，禁止 | 与模板一致，3 | 与模板完全一致 | 与模板一致，禁止 |

正确选项下，回读的完整 `Policy` 与 `UserTemplate` 相同，而不只是上述字段。临时账号均已删除，并通过新 GET 返回 404 确认。当前接口的路径以服务器实际返回及验证为准，不要仅按旧版文档改名。

## 注册行为

- `EMBY_USER_TEMPLATE` 必须配置为准确的模板用户名。
- 独立读取模板，不使用普通用户查询的七天缓存、隐藏状态或禁用状态过滤；模板 ID 和用户名必须匹配。
- 管理员模板、已禁用模板、缺失或无法读取的模板均拒绝创建，不退回默认权限。隐藏模板可以正常复制。
- 只复制权限策略 `userpolicy`，不复制观看记录、收藏或个人显示偏好。转码、同时流数、媒体库限制均属于 `Policy`，不是 `UserConfiguration`。
- 密码设置后，重新读取新账号的完整策略并与模板逐项比对；仅 HTTP 200 不算成功。
- 密码设置或策略校验失败，删除本次创建响应已确认的新账号并回读确认不存在；删除未确认时，错误和严重级别日志明确提示管理员处理。
- 如果创建请求超时或响应身份无效，无法可靠确定服务端是否已创建账号。此时注册失败且不会按用户名盲删已有账号；管理员需核查是否有残留账号。
- 创建失败时邀请码释放，不确认兑换，也不新增本地 Emby 用户记录。

相关代码：`src/app/integrations/emby.py`、`src/app/domains/invitation/service.py`。

## 已有账号

修复注册流程**不会自动覆盖已有用户权限**。历史账号可能有合法的 Premium、独立下载解锁、全库解锁或管理员个别设置，不能把全部账号无差别重置为模板。

处理已有异常账号前，先只读列出明确用户名、当前权限及差异，核对各自已有授权，再确认修复名单和需要改动的字段。当前修复不修改历史账号。

## 历史用户定向对账

`scripts/reconcile_emby_template_permissions.py` 默认只读生成明确名单，`--apply --input <已审阅报告> --output <独立结果文件>` 才修改 Emby。

- 核对音频转码、视频转码、Remux，以及同时流数。仅收紧超出模板的权限，保留比模板更严格的流数限制。
- 全库及受限库访问仅在没有有效 Premium、没有全库解锁记录时回收。全库账号恢复为模板库范围，并结合当前受限库目录补齐子目录限制；不会因旧子目录 ID 变化而把所有账号误判为全库。
- 管理员、模板账号、无本地记录、Emby ID 不匹配或授权状态异常的账号跳过。
- 不修改下载权限、其他策略、数据库授权或账户状态。
- 执行前重新查询身份、完整策略与授权；与审阅名单不一致则跳过。每次写入前保存完整快照，写后回读验证全部策略；检测到同时发生的 Premium/全库授权时恢复原库范围。遇到未预期失败立即停止。
- 审计及结果文件含用户资料，权限为 0600，存放在生产 `data/audits/` 并归档到同步目录外的备份位置。
