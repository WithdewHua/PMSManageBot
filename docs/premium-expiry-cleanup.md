# Premium 到期后的媒体权限清理

## 状态与重试

Premium 到期检查每 5 分钟运行一次，应用启动后约 30 秒执行首次检查。下载撤权和线路解绑都是数据库提交后的外部副作用，不在数据库事务内调用 Plex / Emby。

- 首次到期立即将 `is_premium` 置为 `0`，更新 `premium_status_updated_at`，不因媒体服务器不可用而延长会员资格。
- 保留已经过期的 `premium_expiry_time`，直到下载权限检查、必要的撤权和线路清理完成。`is_premium=0` 且到期时间仍存在的已过期记录会被后续检查重新处理，应用重启不会丢失它们。
- 重试不重复更新状态切换时间，也不重复发送首次到期通知。旧的 Unix 时间戳在单用户到期处理时规范化为带时区的 ISO 时间，确保等待清理期间仍能正常续费。
- 每次尝试都重新检查下载授权。已独立解锁下载，或已经续费 / 成为永久会员的用户，不应被旧的到期任务撤权。权限查询失败时保留待处理记录，不将查询失败当成“没有授权”。
- 只有清理成功后才清空旧到期时间；完成操作必须匹配原到期时间和非会员状态，不能覆盖并发续费后的新状态。
- Plex 返回 `False`、Emby 返回失败元组或 `False`、接口抛异常、缺少媒体账号标识，均不是成功。失败会记录日志并保留待处理记录，单个用户的失败不阻断后续用户。

这复用已有会员字段和定时检查，不新增表、字段或持久化调度任务，无需数据库迁移。

## Plex 调用与诊断

Plex 同步权限通过 PlexAPI 已有的好友权限端点和认证会话更新，只提交 `allowSync`，不经过 `updateFriend` 的媒体库修改分支，也不提交共享媒体库列表。

PlexAPI 4.13.0 的 `updateFriend(..., sections=None)` 会打印：

```text
Section name, number of section object is required changing library sections
```

这条警告本身不代表权限请求失败。不要为消除警告传入所有媒体库，否则可能扩大用户的媒体库访问范围。

更新失败时记录原始异常及堆栈。持续失败应根据实际异常排查，例如 Plex 认证或权限问题、网络超时、服务端错误；自动重试不会修复失效的凭证。向外提供日志前应检查并遮蔽令牌等敏感信息。

## 已经发生的历史失败

旧版本会在调用媒体服务器之前清空到期时间。因此，旧版本已清空的失败记录无法仅凭当前数据库区分于正常非会员，更新程序不会自动扫描并撤销所有非会员的媒体权限。

对历史失败，应先根据日志和实际媒体权限核对账号，并确认当前没有有效 Premium 或独立下载授权。维护者确认后，才可使用 `scripts/list_expired_download_holders.py --apply --input <json>` 处理明确列出的账号。该脚本的默认扫描针对数据库中已有下载解锁标记的记录，不保证发现仅在媒体服务器上残留的权限，不能直接将扫描结果视为撤权授权。

禁止用 `scripts/sync_download_permissions.py` 做撤销或对账；它是单向同步脚本。
