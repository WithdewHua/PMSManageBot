# Premium 流量规则说明

## 概述

当前 Premium 流量采用“累计欠账余额”模型。

- 普通用户每日基础 Premium 免费额度：`12GB`
- Premium 用户每日基础 Premium 免费额度：`24GB`
- 欠账最多允许累计到 `2 天基础额度`
- 超过欠账上限的部分，按积分规则扣费

说明：

- 这里只统计 `Premium 线路流量`
- 普通线路流量不参与这套免费额度和欠账结算

## 核心规则

### 1. 每天都有基础额度

系统每天会给用户一份基础 Premium 免费额度：

- 普通用户：`12GB`
- Premium 用户：`24GB`

### 2. 只记录欠账，不记录正余额

系统只会记录“还欠多少 Premium 免费额度”，不会记录“还剩多少没用完的历史余额”。

这意味着：

- 当天没用完的基础额度，不会结转到第二天
- 只有超出的部分，才会进入“欠账”

### 3. 当天基础额度会先抵扣历史欠账

如果用户之前已经欠了额度，那么新一天的基础额度会先用来偿还旧欠账。

偿还后，剩余部分才算当天还能继续免费使用的基础额度。

### 4. 欠账最多保留 2 天额度

系统允许累计欠账，但最多只能保留到 `2 天基础额度`：

- 普通用户最多欠 `24GB`
- Premium 用户最多欠 `48GB`

如果结算后欠账超过这个上限：

- 超出上限的部分不会继续滚动
- 会直接进入积分扣费

### 5. 单日最多可用到多少

如果用户在当天开始时没有历史欠账，那么当前实现下，单日理论上最多可以先用到 `3 倍基础额度`，再开始扣积分。

原因是：

- `1 倍基础额度` 来自当天额度
- 额外允许日终最多保留 `2 倍基础额度` 的欠账

因此：

- 普通用户：单日最多约 `36GB` 后才开始扣积分
- Premium 用户：单日最多约 `72GB` 后才开始扣积分

但这不是“每天固定有 3 倍额度”，而是：

- 只有在当天开始时没有历史欠账时，免扣费空间才最大
- 如果当天开始前已经有欠账，当天还能继续使用的免扣费空间会变少

### 6. 前一天没用完，不会留到第二天

例如普通用户某天只用了 `3GB` Premium 流量：

- 当天剩余 `7GB` 只在当天有效
- 第二天不会变成 `17GB`

## 结算方式

系统按天结算前一天的 Premium 流量。

结算时会做这些事情：

1. 读取当前历史欠账
2. 用当天基础额度优先偿还旧欠账
3. 计算前一天实际 Premium 流量是否又产生新的欠账
4. 如果欠账超过 `2 天额度` 上限，则对超出部分扣积分

### 身份变化时如何结算

如果用户在两天之间发生了 Premium 身份变化，当前实现遵循这条原则：

- 昨天的流量，按昨天的身份结算
- 今天还能使用多少基础额度，按今天的身份计算

例如：

- Day1 不是 Premium，超出后形成欠账
- Day2 变成 Premium

那么：

- Day1 结算时，按普通用户基础额度 `12GB` 计算
- Day2 使用时，按 Premium 用户基础额度 `24GB` 计算
- Day2 的基础额度会先偿还 Day1 留下的欠账，再计算当天还剩多少基础额度

## 积分扣费规则

超过可结转欠账上限后，超出部分按以下规则扣积分：

- 每 `10GB` 扣 `5` 积分
- 不足 `10GB` 按 `10GB` 一档计算

例如：

- 超出 `1GB`，按 `10GB` 计费
- 超出 `11GB`，按 `20GB` 计费

## 示例

### 示例 1：普通用户，次日自动还清

普通用户每日基础额度为 `12GB`。

Day1：

- 使用 Premium 流量 `18GB`
- 当天基础额度 `12GB`
- 形成欠账 `6GB`

Day2：

- 系统发放当天基础额度 `12GB`
- 先偿还旧欠账 `6GB`
- 欠账归零
- 剩余 `6GB` 只可在 Day2 当天使用

### 示例 2：普通用户，超过欠账上限后扣积分

普通用户欠账上限为 `24GB`。

假设某次结算后：

- 旧欠账已经很高
- 新增 Premium 流量继续超出
- 结算后本应欠 `27GB`

则：

- 只保留 `24GB` 欠账
- 超出的 `3GB` 进入积分扣费
- `3GB` 按 `10GB` 一档计算，扣 `5` 积分

### 示例 3：当天没用完不会结转

Premium 用户每日基础额度为 `24GB`。

Day1：

- 只用了 `6GB`
- 剩余 `14GB` 当天作废

Day2：

- 仍然只有新的 `24GB` 基础额度
- 不会变成 `34GB`

## Premium 身份变化的处理

系统会记录 Premium 状态切换时间，用于处理结算日前后升级或过期的边界情况。

以下情况会影响结算时采用的额度档位：

- 普通用户升级为 Premium
- Premium 用户到期变回普通用户

系统会尽量按照“结算那一天用户实际应当使用的档位”来计算。

## 前端展示说明

用户中心会显示以下信息：

- `Premium 日基础余额`
  - 表示今天这一天、在扣除历史欠账影响后，当前还剩多少基础额度
  - 这里不等于“总共还可以免费跑多少未来流量”

- `当前欠额`
  - 表示已经形成、尚未还清的历史欠账

- `预计结算后欠额`
  - 表示按今天目前的 Premium 流量继续结算，今天结束后预计仍会留下的欠账
  - 这不是“今天没用完的额度会带到明天”
  - 只有超出基础额度形成的欠账，才会进入后续偿还流程

## 当前实现总结

一句话概括：

> 每天给一份基础 Premium 免费额度，先还旧账，再覆盖当天；当日没用完作废；超出部分记欠账；欠账最多保留 2 天额度，再超出就扣积分。
