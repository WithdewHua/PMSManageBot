## Context

21 点已部署至真实环境（见迁移 `y5z6a7b8c9d0` 的注释），存量手牌需要保持结算与评判口径不变。动机见 proposal.md「Why」，行为契约见 `specs/blackjack/spec.md`。

约束本次设计的既有事实：

- **参数快照哲学**：`BlackjackHand` 已有五列参数快照（`rake_bp_on_profit` / `rake_jackpot_bp` / `blackjack_payout` / `dealer_hits_soft_17` / `hand_timeout_minutes`），结算与评判一律读快照而非当前配置，使管理员改配置不影响已发出的手牌。
- **决策准确率是零方差口径**：`recommend_action()` 是纯函数，同一局面恒得同一建议。这是准确率能作为主榜口径与游戏王勋章条件的前提。
- **响应过滤的单一入口**：`BlackjackHandResponse.from_hand()` 是庄家暗牌与随机种子的唯一过滤点（设计决策 10），不在路由层逐处 if 判断。
- **牌靴不跨手复用**：`deck_seed` 每手一个，`next_card_index` 每手从 0 起。
- **迁移必须用 `batch_alter_table`**：SQLite 不支持 `ALTER TABLE ADD CONSTRAINT`，需整表重建；PostgreSQL 上 batch 模式透传为普通 ALTER。

## Goals / Non-Goals

**Goals:**

- 投降的落地不引入新的架构模式——动作、结算、评判、快照四条链路各自复用既有形状
- 存量手牌的准确率评判口径逐位不变
- 关闭开关即可完整回滚，不需要回滚代码或数据

**Non-Goals:**

- 不做分牌、保险、早投降（Early Surrender）
- 不动 `resolve()` 的胜负判定语义——投降不是一种胜负结果
- 不新增榜单，也不调整既有榜单的排序口径

## Decisions

### 1. 返还比例硬编码为二分之一，不做配置项

基本策略的三格投降建议正是按 0.5 推导的：只有当某局面的期望低于 −0.5 时投降才是最优。比例若可调（比如改成 0.4），该投降的局面集合会跟着变（只有期望低于 −0.6 的局面才该投），策略表必须同步重算。

而策略表是决策准确率的依据，准确率又是主榜口径与游戏王勋章的条件。一个比例旋钮会让整条评判链失去稳定依据，历史准确率也无法与当前口径比较。

**替代方案**：做成可配置，并按比例动态推导策略表。否决——动态推导需要对每个「玩家手牌 × 庄家明牌」组合做完整的期望值计算，远超当前查表式 `recommend_action()` 的实现，且会把一个可变参数注入到「零方差」的准确率口径里。

只让开关可调、比例固定，是唯一能同时满足「管理员可回滚」与「评判口径稳定」的组合。

### 2. 新增 `surrender_enabled` 快照列，默认值使存量手牌保持「无投降」口径

与既有五列快照同一哲学。若只读当前配置会有两处坏掉：

- 管理员在玩家思考期间关闭开关，玩家点已经渲染出来的投降按钮会被拒
- 存量手牌的准确率被重算时口径漂移——原本判为「16 对 10 该要牌，玩家要牌，正确」的决策，在开关打开后会变成「该投降，玩家要牌，错误」。主榜排名与勋章资格会凭空变动

迁移用 `server_default="0"`：所有存量手牌落到「发牌时投降不可用」，其评判继续走不含投降的策略表，逐位不变。新发出的手牌按当时配置写入。

### 3. 策略表用 `"RH"` / `"Rs"` 回退记号，与既有 `_D_ELSE_*` 完全对称

`_hard_strategy()` 现在返回 `"D"` / `"Ds"` 记号，由 `recommend_action()` 按 `can_double` 落到具体动作，回退方向按局面各异（`"D"` 回退到要牌，`"Ds"` 回退到停牌）。

投降复用这个形状，且**同样需要两个方向**：`"RH"` = 能投降就投降否则要牌，`"Rs"` = 能投降就投降否则停牌。硬 15、16 的四格在不能投降时本就该要牌，而 H17 下的硬 17 对 A 该停牌——若一律回退到要牌，投降关闭的手牌（含全部存量手牌）在该格的评判会由「停牌正确」翻成「要牌正确」，直接违背决策 2 承诺的「存量手牌口径逐位不变」。

`recommend_action()` 新增 `can_surrender` 参数，与 `can_double` 并列。不引入新模式。

覆盖的格子（`up` 为庄家明牌点数，A 记 11）：

| 条件 | 局面 | 记号 |
|---|---|---|
| 恒定 | 硬 16 对 9、10、11 | `RH` |
| 恒定 | 硬 15 对 10 | `RH` |
| 仅 H17 | 硬 15 对 11 | `RH` |
| 仅 H17 | 硬 17 对 11 | `Rs` |

H17 两格要一并实现：`dealer_hits_soft_17` 已经是策略表的既有参数，管理员可以打开，漏掉会让那种配置下的评判出错。

这些格子必须判在 `_hard_strategy()` 的**最前面**：硬 17 对 A 会被 `total >= 17` 的停牌提前返回，硬 15、16 会被 13–16 的停牌/要牌提前返回，放在后面等于永不生效。

### 4. 投降不经 `resolve()`，走独立的结算路径

`resolve()` 的职责是「给定双方最终牌面判定胜负与赔付」，它的三元组返回值（outcome / return_multiplier / profit_multiplier）里投降没有对应位置——投降没有胜负，`profit_multiplier` 恒为 0 但 `return_multiplier` 是 0.5 而非 stake 的整数倍。

硬塞进 `resolve()` 需要给它加一个「玩家是否投降」的入参，而该函数此刻的输入只有牌面——加入一个与牌面无关的分支会破坏它「纯粹按牌面判定」的语义。

`blackjack_surrender()` 照 `blackjack_stand()` 的抢占模式写：先把 status 从玩家回合推进到已结算（抢占失败即说明已被其他请求或超时任务处理，直接返回而不重复赔付），然后按固定口径入账。比停牌更短——不需要庄家补牌。

### 5. 投降后照常公开庄家暗牌

「隐藏信息」需求规定暗牌在手牌进入庄家回合或已结算后公开。投降的手牌是已结算，故自动公开，`from_hand()` 无需特判——这正是设计决策 10 想保住的性质。

安全上零风险：牌靴不跨手复用，本手已终结，暗牌不含任何对后续手牌有用的信息。

体验上是主动选择而非将就：玩家看到暗牌才能判断这次投降是对是错，与决策准确率的教学定位一致。代价是偶尔会看到「其实能赢」而后悔——但基本策略的要点恰恰是「长期正确的选择在单次上经常显得错」，展示暗牌反而让这一课落地。

**替代方案**：投降后隐藏暗牌。否决——需要给 `from_hand()` 加一个基于 outcome 的特判，把单一过滤入口变成两条规则，收益仅是回避一种情绪。

### 6. 榜单查询零改动即满足新口径

`_blackjack_rank_rows()` 现有实现已经自动满足 spec 的胜率口径：

- 分子 `win_flag` 是 `outcome IN (win, blackjack)`，`"surrender"` 不在其中 → 自动不计入
- 分母 `COUNT(id)` 过滤 `status IN TERMINAL_STATUSES`，投降的 status 是已结算 → 自动计入

单手最大赢利榜同理：投降的净赢利为 `0.5B − B = −0.5B < 0`，被既有的 `max_win > 0` 过滤掉。

本次只需在个人统计（`get_user_blackjack_stats`）里新增投降手数的计数，榜单侧一行不改。

### 7. 免抽水额度不因投降退还

免抽水额度在**发牌时**消耗：`hands_today < free_hands` 判定后把 `rake_waived` 快照到手牌上。若该手随后投降，额度形式上「浪费」了——但投降本就不产生抽水，实际并无损失。

**替代方案**：投降时退还额度。否决，且这是必须否决的——退还会制造一条套利路径：首手发牌 → 看到坏牌 → 投降 → 额度保留 → 继续打，直到拿到值得用掉免抽水的牌。这把一个无条件的习惯钩子变成了可被挑选时机的资源。

维持「发牌即消耗」的既有语义，不做特殊处理。

### 8. 超时与并发复用既有机制

- **超时任务**：投降后手牌是终态，已排的 `blackjack_timeout_{hand_id}` 触发时命中 `already_settled` 分支，只记日志。零改动。
- **重复请求**：与停牌同样靠状态抢占保证幂等，满足「对同一手牌的重复动作请求 SHALL NOT 导致重复赔付」。
- **惰性清理与定时兜底**：投降的手牌已是终态，不会被 `sweep_timed_out_blackjack_hands()` 选中。零改动。

## Risks / Trade-offs

**[玩家靠投降刷手数冲榜门槛]** → 无经济动机，不需额外防护。投降每手固定亏 0.5 倍注额，而正常打完的期望亏损不到 0.01 倍注额——刷榜成本高出五十倍以上。且投降计入胜率分母不计入分子，刷得越多胜率越低。

**[准确率评判变严，影响游戏王勋章]** → 存量手牌由快照隔离，逐位不变。新手牌在那几格上的评判确实变严（原本「要牌」正确，现在「投降」才正确），但同时也给了玩家一个更容易做对的选择——该投就投，比判断要牌到几点更简单。勋章阈值（`badge_min_accuracy = 80`）不需要调整。

**[误点投降不可逆]** → 前端加二次确认。投降是本活动唯一「点下去就没有任何后续操作」的动作，加倍至少还会发一张牌。

**[抽水收入与奖池注入下降]** → 玩家期望改善约 0.6 个百分点，对应抽水的同量级下降（体现为「原本会赢并被抽水的手牌减少」）。幸运奖池注入相应变慢。可观测、可回滚：管理面板关闭开关即恢复原状，不需要回滚代码或数据。

**[开关关闭期间发出的手牌，在开关打开后仍不能投降]** → 这是快照的预期行为，不是缺陷。但需要在管理面板的开关旁注明，否则管理员打开开关后会疑惑为何部分进行中的手牌仍无投降入口。

## Migration Plan

1. 新增一个 alembic 迁移，`down_revision = "y5z6a7b8c9d0"`，用 `batch_alter_table` 给 `blackjack_hand` 加 `surrender_enabled`（`SMALLINT`, `nullable=False`, `server_default="0"`），并配 `CheckConstraint("surrender_enabled IN (0,1)")`。
2. 默认配置新增 `surrender_enabled: True`。存量手牌因 `server_default="0"` 落到「无投降」，与其发牌时的真实情况一致。
3. 后端与前端一并上线。开关默认开启，投降对新手牌立即可用。

**回滚**：管理面板关闭投降开关即可。已投降的手牌保持已结算，不受影响；新手牌不再提供投降。代码与数据均无需回滚。若需彻底移除，迁移的 `downgrade()` 直接删列——历史手牌的 outcome 中会残留 `"surrender"` 值，其 `payout_credits` 已正确记账，统计口径仍可用。
