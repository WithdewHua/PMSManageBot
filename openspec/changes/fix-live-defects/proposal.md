## Why

各个领域提升变更都遵守"只重构、不改行为"：调研中发现的缺陷，只用测试把现状固定下来，统一交给一个缺陷修复变更处理。这个变更此前并不存在。

本变更收拢这些缺陷，并补上复核时新发现的问题。复核在 2026-09-28 进行，所有缺陷都在内存 SQLite 上加外部服务替身复现过；只在 PostgreSQL 上出现的问题，给出了生成的 SQL 和报错码。

按影响分为四类：

**积分会算错（多发、少发或重复扣）**

- **Plex 账号同步中途中止**：库里没有对应记录的 Plex 好友，会让每天的全量同步在该处中止，异常只打印到 stdout。中止点之后的用户不改名；plex_id 和邀请记录的回填、头像刷新整段不执行。回填不了的用户没有观看积分，邀请人也拿不到奖励。自 `844b879`（2025-12）起存在。
- **观看积分结算**：
  - 某个用户的会员流量扣费超过余额时，`deduct_tx` 抛出余额不足，当天排在他之后的用户全部中止。条件不变时每天都会中止。这是 `83b0fa4` 引入的回归：会员流量费按设计允许把余额扣成负数，这也是系统中唯一允许余额为负的情况，而改造时套用了不允许透支的 `deduct_tx`。
  - 中途失败后的状态：失败点之后的 Plex 用户当天积分永久漏发；已结算用户的邀请人奖励漏发；幽灵会话补偿没有标记，下一次会再发一遍。
  - 没有结算记录，手工补跑 `legacy-credit-sync` 会重复发放。
  - 邀请人通知里的总积分多算了一次奖励（仅显示）。
- **自建线路月度结算**：
  - 没有结算记录，重跑、多实例、删除后同名重建，都会重复发积分。
  - 结算时排除线路所有者自用流量，比较用户名时区分大小写，大小写不一致就会多发。
  - 流量查询失败时返回 0，被当作没有流量静默跳过。
  - 每月 1 日结算之前删除线路，上个月的结算会丢失。
- **竞拍**：
  - 结束时不检查是否已结束，也不加锁。重复结束、定时任务和管理员同时结束，都会重复扣得主的积分、重复通知。
  - 兜底任务 `finish_expired_auctions` 的 `GROUP BY` 在 PostgreSQL 上报错（42803），永远结束 0 场却提示成功。
  - 启动恢复只处理 50 条。丢了调度的竞拍永远结束不了。
  - 竞拍结束后，迟到的出价仍能写入并覆盖当前价。
- **永久会员购买会员**：先授予（对永久会员返回 None）、再扣分并提交，然后格式化到期时间报错，返回 500。积分已扣，会员没变。
- **零额积分变动报错**：`make-credit-changes-atomic` 之后，`add`/`deduct` 对 0 抛错。
  - 默认配置下就会触发：
    - NSFW 锁定退款为 0 时，媒体服务器上已移除权限，库里标志没清，用户之后无法再次解锁。
    - 观看结算中，邀请奖励舍入为 0 时，后续邀请人的奖励全部丢失。
  - 后台把各项价格设为 0 时，有 9 处在外部动作已完成后报错。
- **下载解锁**：账号未绑定时照样扣分并返回"解锁成功"；并发双击会扣两次。维护者已确认修掉。

**权益或数据不一致**

- **会员到期不撤销下载权限**：撤销代码读取的字典键不存在，从 2026-01 起就是死代码，到期会员至今保留下载权限。
- **会员到期整批中断**：到期用户的线路为 NULL 时，`in None` 抛错并中断整批。后续用户的会员线路没有解绑，也收不到通知；由于会员标志已经提交，下一轮不会再选中他们。
- **夺宝自动开期**：没有幂等，重复执行会并行开两期；任务丢失（停机、misfire）后开期静默停止，也没有启动补救。
- **Plex 注册**：
  - 不绑定 TG 的凭码注册不建本地记录，邀请记录的 plex_id 永远不回填，邀请人永久少拿 10%。
  - 人数上限用 `== 100` 判断，一旦越过 100 就彻底失效。
- **捐赠登记**：登记已提交、并已通知管理员之后，任何一步出错都会删除"该用户最新一条"登记；反查失败时又不删除，重复提交可能被批准两次。

**请求被报成失败，或出现 500**

- **自建线路**：
  - 上线和续期在提交后导入不存在的 `config`，数据已经提交，接口却报失败，并跳过频道通知。用户重试续期会重复延长有效期。这是 B1 引入的回归。
  - 提交申请在提交后读取不存在的 `settings.TG_ADMIN_IDS`，线路已经建好，用户却看到失败，管理员收不到通知。
  - 这几处错误响应还回显了异常原文和服务器路径。
- **竞拍无人出价**：结束时调用 `send_message_by_url(None)` 报错，流拍分支是死代码。
- **被外层 `except Exception` 改成 500 的业务拒绝**：
  - 邀请码的 `points-info` 和 `generate`：未绑定用户的 404。
  - 预言创建和投稿：截止时间的 400。
  - 排行的流量榜：日期格式的 400。
  - 转盘和媒体权限各有一处。
- **排行接口出错时返回 200 加空列表**：违反 `rankings` 规格中"失败与无数据的区分"。
- **bot `/info`**：缺少统计行时抛 TypeError，用户收不到回复。
- **捐赠通知**：倍率写死为 2，默认配置是 5，通知少报了实际入账。

**信息探测**

- 线路预览接口不读取当前用户，可以用任意 Plex 邮箱或 Emby 用户名，查出对方是否注册、是否会员、正在用哪条线路。

生产环境跑的是重构前的代码。除 B1 和 `make-credit-changes-atomic` 引入的回归外，上面的缺陷在生产上都存在。维护者决定：只在 dev 上修复，随重构版本发布，不单独做生产热修复。

## What Changes

- **积分变动的零额规则**：`credits` 的增减接口把 0 视为无操作，返回变化为 0 的结果，不再抛错；负数仍然拒绝。"价格为 0"一律按免费处理，"退款为 0"一律按无退款处理，调用方不再各自判断。
- **观看积分结算**：
  - 每个用户的结算，连同邀请人奖励和该用户幽灵补偿的标记，在同一个事务里完成。
  - 新增结算记录表，按服务、账户和日期唯一；同一天重跑和手工补跑都是幂等的。
  - 单个用户失败不影响其他用户；失败的用户列进管理员汇总。
  - 会员流量扣费恢复原来的设计：按应扣数额全额扣除，允许余额变为负数。为此 credits 新增一个只供会员流量费使用的透支扣费接口，其余扣费仍然不允许透支。
  - 扣费汇总只列出已提交的扣费；邀请人通知显示实际余额。
- **账号同步**：缺少本地记录的好友记日志后跳过；每个用户、每个阶段单独处理失败，不再中止整次同步；按邮箱解析 plex_id 时不区分大小写。
- **Plex 注册**：
  - 人数上限改为 `>=`。
  - 不绑定 TG（包括因已绑定其他 Plex 而降级）时，也建一条未绑定记录，并回填 plex_id，与 Emby 一致。
  - `/bind/plex` 能绑定"按邮箱找到、但还没有 plex_id"的记录，绑定时回填邀请记录。
  - 并发绑定被拒绝时，提示"已被绑定"，不再是"未知错误"。
- **邀请码接口**：未绑定用户调用 `points-info` 和 `generate` 时，按现有的 200 契约返回"用户未绑定 Plex/Emby 账户"。
- **自建线路**：
  - 新增结算记录表，一条线路一个月只结算一次。删除前的结算与删除在同一个事务里，并补结当月之前还没结算的月份。
  - 结算时，流量查询失败就中止这条线路的结算，下次重跑补上。
  - 排除所有者时不区分大小写。
  - 月份一律按 `settings.TZ` 计算。
  - 修复上线、续期和提交申请在提交后的报错。
  - 错误响应不再回显异常原文。
- **竞拍**：
  - 结束在一个事务里完成：先锁住竞拍行，已结束就不再扣分和通知。只有完成状态转换的一方发通知。
  - 无人出价时发流拍通知。
  - 兜底任务改为逐场调用同一个结束函数，每 10 分钟运行一次。
  - 启动时恢复全部进行中的竞拍。
  - 出价时锁住竞拍行，已结束或已过期的竞拍拒绝出价。
  - 管理后台对已过期、尚未结束的竞拍也显示结束按钮。
- **夺宝自动开期**：在源期上记录到期时间和后继期数，开期时锁住源期，已有后继就跳过；启动时和定期扫描补开到期未开的期数。需要 schema 迁移。
- **会员**：
  - 购买：永久会员在扣分前被拒绝（400，与前端提示相同）；扣分和授予在同一个事务里完成。
  - 到期任务：逐个用户在一个事务里降级并解绑会员线路；线路为 NULL 时按"未绑定线路"处理。
  - 到期后，只撤销"会员附带"的下载权限，永久解锁的不动。撤销前的检查失败时不撤销，并汇总给管理员。
  - 已经到期、至今仍保留下载权限的存量用户，由只读脚本列出名单，经维护者确认后再撤销。
- **下载解锁**：扣分和设置标志在同一个事务里完成，锁内复查标志。未绑定时不扣分，返回"请先绑定 Plex/Emby 账户"；已解锁时不扣分，返回原来的"无需重复解锁"。
- **业务拒绝不再变成 500**：在列出的接口中，`except Exception` 之前先原样抛出 `HTTPException`，恢复原来的状态码和文案。
- **排行接口**：获取失败时返回 500 和现有文案，前端已有的"失败加重试"随之生效。名字或头像出错时，只让该行留空，不影响整榜。
- **捐赠**：
  - 登记在同一事务中返回新记录，不再反查，也不再在失败时删除登记。管理员通知在提交后尽力发送。
  - bot 通知显示实际入账的积分。
- **bot `/info`**：缺少统计行时，积分和捐赠额显示为 0。
- **线路预览接口**：查询的是当前用户自己绑定的账号时，结果照旧；其他账号只返回完整的线路目录，当前线路为空，不再透露是否注册和是否会员。前端不用改。
- **明确不修**：`/api/user/users` 不加管理员校验。维护者判断：排行榜本来就公开了所有用户的捐赠额和积分，加校验意义不大。

## Capabilities

### New Capabilities

- `credits`：积分增减中零额的处理，以及会员流量费这一唯一的透支例外。如果 `make-credit-changes-atomic` 先归档，这一条就合并进它建立的 `credits` 规格。
- `watch-rewards`：观看积分每日结算的幂等性、失败隔离、会员流量费的扣除和通知内容。
- `media-account-sync`：Plex 和 Emby 账号信息每日同步的容错。
- `account-registration`：凭码注册、Plex 人数上限、未绑定 TG 的注册、媒体账号绑定，以及邀请码接口对未绑定用户的响应。
- `custom-lines`：自建线路的月度结算、删除时的结算、月份口径，以及状态变更接口的响应。
- `auction`：竞拍的结束、流拍、兜底、启动恢复和出价截止。
- `treasure`：夺宝满员后的自动开期。
- `premium`：会员购买和会员到期。
- `media-access`：付费下载解锁和 NSFW 锁定退款。
- `api-error-responses`：业务拒绝的状态码不被兜底改写，错误响应不回显内部异常。
- `donation`：捐赠登记和登记通知。
- `user-info`：bot `/info` 的回复。
- `line-binding`：线路预览接口的信息范围。

### Modified Capabilities

- `rankings`：补充接口层的要求，即获取失败必须以失败响应返回，不能返回空列表。

## Impact

- **代码**：accounts、invitation、identity、watch_rewards、custom_lines、traffic、auction、treasure、prediction、luckywheel、premium、media_access、lines、rankings、donation、profile、credits 这些领域，以及 `schedule.py`。
- **前端**：
  - 会员解锁对话框在 400 时读取 `detail`。
  - 竞拍管理中，结束按钮的显示条件改为"进行中"，不再依赖结束时间。
  - 其余修复前端不用改。
- **数据库**：三个 alembic 迁移，分别是观看结算记录表、自建线路结算记录表和夺宝期数上的两列。都不回填历史数据。
- **调度**：竞拍兜底任务从每天 02:00 改为每 10 分钟；新增夺宝补开的扫描。调度快照和任务注册测试要同步更新。
- **一次性操作**：只读脚本列出"会员已到期、仍有下载权限、没有永久解锁"的用户，经维护者确认后执行撤销。
- **不追溯**：以往漏发、多发的积分都不补发，也不追回；已经丢失的每日 Plex 数据无法重建。
- **依赖和顺序**：
  - 在 `promote-gift-pack-domain` 之后实施。它提供了 `grant_premium_days_tx`、`unlock_download_tx` 和积分 `*_tx` 的缓存失效自登记，另外它正在修改的文件也要避免冲突。
  - 在其余提升变更之前实施。这样那些变更固定的就是修复后的行为，不用先固定缺陷、再翻转断言。
  - 例外："未绑定 TG 的 Plex 注册"一项依赖 `promote-account-domains` 提供的 `PlexUserIdResolved` 事件和具名任务 `invitation.resolve_plex_id`，放在那个变更之后单独实施。
